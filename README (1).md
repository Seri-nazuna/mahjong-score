# 麻雀 点数計算機

翻数と符を選ぶと、和了点と支払いの内訳を表示するWebツールです。
HTML / CSS / JavaScript のみで作っており、ブラウザで開けばそのまま動きます。

**公開URL：** https://seri-nazuna.github.io/mahjong-score/

---

## 作ったきっかけ

大学の友人に麻雀を教えていて、一番の壁になるのが点数計算でした。

役や鳴きは打ちながら覚えられますが、点数だけは急に「暗記」を要求されます。
符計算は形で覚えるものですし、そもそも符を数えなくて済む場面も多いので、
まずは**翻と符から点数が出せる状態**を作るのが先だと考えました。

もうひとつ、自分自身の問題もありました。
槓が複数入ったときなど、めったに出ない符の点数がその場で分からない。
点数表を丸暗記していない限り詰まる場面で、これも同じツールで解決できます。

## 何を重視したか

麻雀は、人に全部教わるより自分で分かった方が面白いゲームだと思っています。
点数を毎回こちらが答えてしまうと、友人はいつまでも自分で出せるようにならないし、
何より楽しくない。

そこで、**答えを出すだけの道具にしない**ことを設計の軸にしました。

- 結果と一緒に `30符 × 2^(2+4) = 基礎点 1920` と計算式を併記する
- 支払いを「親から3900・子から2000ずつ」と分けて出し、卓上の動きと対応させる
- 金額を点棒の組み合わせに分解して表示する

使っているうちに構造が頭に入って、最終的にツールが要らなくなるのが理想です。

## 何を作らないか決めた

最初は「牌の並びを入力すると点数が出る」ものを考えていました。
ただ、必要な処理を分解すると難易度がまったく違うことが分かりました。

| 機能 | 必要な処理 | 判断 |
|---|---|---|
| 手牌から役を判定する | 和了形の分解、複合役の優先順位、例外役の処理 | 見送り |
| 手牌から符を数える | 面子構成・待ちの形・門前かどうかの判定 | 見送り |
| 翻数と符から点数を出す | 計算式と切り上げ処理のみ | **採用** |

友人が詰まっていたのも、自分が困っていたのも3番目だけでした。
作れる範囲から機能を決めるのではなく、解きたい課題から決める順序を意識しています。

## なぜ点数表を持たせなかったか

符と翻の組み合わせごとに点数を書いた表をデータとして持てば、
検索するだけで答えは返せます。実装としてはその方が単純です。

それでも計算式で持つことにしたのは、次の2点からです。

ひとつは、槓が絡んだときの70符・90符・110符といった稀な組み合わせまで表に書き出すと、
4翻以下だけで200近い数値を手入力することになり、打ち間違いを見つけにくいこと。
自分が実際に困っていたのがまさにその稀な符なので、そこが抜けると意味がありません。

もうひとつは、表からは「30符4翻の子ロンは7700点」しか取り出せないことです。
このツールで見せたいのは答えではなく、1920を4倍して切り上げると7700になるという道筋の方でした。
式で持っていなければ、画面に計算過程を出すことができません。

## 点数の計算方法

### 1. 基礎点

```
基礎点 = 符 × 2^(2 + 翻)
```

5翻以上は符に関係なく固定値になります。

| 翻数 | 呼び名 | 基礎点 |
|---|---|---|
| 5翻 | 満貫 | 2000 |
| 6〜7翻 | 跳満 | 3000 |
| 8〜10翻 | 倍満 | 4000 |
| 11〜12翻 | 三倍満 | 6000 |
| 13翻以上 | 役満 | 8000 |

4翻以下でも、計算結果が2000を超えた場合は満貫として2000で頭打ちになります。

### 2. 支払い

| | ロン | ツモ |
|---|---|---|
| 親 | 基礎点 × 6 | 基礎点 × 2 を子3人から |
| 子 | 基礎点 × 4 | 親から 基礎点 × 2 ／ 子2人から 基礎点 × 1 |

### 3. 切り上げ

支払い額は**それぞれ個別に**100点単位で切り上げます。
合計してから切り上げるのではない、というのが実装上の注意点です。

例：子・30符4翻のツモ

- 基礎点 = 30 × 2⁶ = 1920
- 親から 1920 × 2 = 3840 → **3900**
- 子から 1920 × 1 = 1920 → **2000**（2人分）
- 合計 7900点

先に合計してから切り上げると7700点になり、実際の点数表と一致しなくなります。
